Asignatura: INF-8239 Ciencia de Datos II

Autor: Edwin Ramón José Nolasco

Código: INF8239.TF.01

Trabajo final

Mandato académico · 25 puntos

Propósito. Resolver un problema verificable mediante ciencia de datos y producir evidencia que permita comprender, reproducir y utilizar responsablemente el resultado.

1. Modalidades

Modalidad A · Proyecto aplicado: desarrolla y evalúa una solución de ciencia de datos para describir, predecir, clasificar, segmentar o generar información útil.

Modalidad B · DSS: integra datos, modelos, reglas o restricciones, explicación, recomendaciones y supervisión humana para apoyar una decisión identificada.

2. Participación y alcance

El proyecto puede ser individual o grupal. Se permiten equipos de hasta nueve integrantes. La cantidad de miembros determina el alcance mínimo:

IntegrantesAlcance mínimo
1Modalidad A o B; baseline y un modelo candidato; 6 pruebas; documentación, repositorio y demostración.
2–3Modalidad A o B; baseline y dos modelos; 8 pruebas; documentación, control de versiones y demostración integrada.
4–5Modalidad A o B; baseline y dos modelos; 8 pruebas; documentación y demostración.
6–7Tres modelos; análisis comparativo; 12 pruebas; aplicación, API o tablero funcional.
8–9Modalidad DSS obligatoria; aplicación funcional; API o pipeline; 16 pruebas; CI, Model Card, auditoría y monitoreo.

El docente puede rechazar un tamaño de equipo cuando el tema no permita distribuir trabajo sustantivo. Los grupos de 8–9 deben transformar el tema en un DSS o seleccionar otro.

3. Entregables obligatorios

  1. Repositorio GitHub accesible al docente desde el primer hito.
  2. Definición del problema, decisor y criterios de éxito.
  3. Dataset, ficha de procedencia y auditoría de calidad.
  4. EDA reproducible y pipeline de preparación.
  5. Baseline, modelos requeridos y evaluación justificada.
  6. Análisis de errores, limitaciones y riesgos.
  7. Producto funcional conforme al rango del equipo.
  8. Pruebas automatizadas y evidencia de ejecución.
  9. README de instalación, arquitectura y uso.
  10. Informe final, Model Card cuando aplique y demostración.
  11. Declaración de uso de IA de cada integrante.

4. Hitos

HitoEvidencia
H1Tema, modalidad, integrantes, roles, problema, decisor, decisión y repositorio.
H2Datos, auditoría, EDA, issues, criterios de aceptación y baseline.
H3Modelos, pruebas, métricas y análisis de errores.
H4Producto/DSS, interfaz, API o pipeline y documentación.
H5Auditoría final, Model Card cuando aplique, versión y ensayo de defensa.

5. Defensa individual

Cada integrante deberá explicar su contribución, localizarla en GitHub, justificar una decisión metodológica, interpretar una métrica, responder sobre el sistema completo y realizar una modificación breve cuando sea solicitada. La ausencia de dominio individual puede producir calificaciones diferentes dentro del mismo equipo.

6. Entrega

Se entregarán el enlace del repositorio, versión etiquetada, informe PDF, enlace o instrucciones de ejecución, matriz de contribuciones y declaración de IA. Un ZIP sin historial no sustituye el repositorio.

Condición de autoría. Toda persona incluida como integrante debe poseer evidencia técnica y defender el producto. La coautoría nominal sin contribución verificable no será aceptada.
